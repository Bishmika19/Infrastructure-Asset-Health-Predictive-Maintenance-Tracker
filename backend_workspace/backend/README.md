# Backend (FastAPI modular monolith)

Infrastructure Asset Health & Predictive Maintenance Tracker API. Design:
`kavia-docs/CodeWiki/Specs/DetailedDesigns/fastapi-backend-structure.md`.

- Install: `python3 -m venv venv && source venv/bin/activate && pip install -r requirements.txt`
- Run: `uvicorn src.api.main:app --host 0.0.0.0 --port 8000` (re-exports canonical `app.main:app`)
- Health: `GET /livez` (liveness) and `GET /healthz` (`HEALTHCHECK_PATH`; 503 when the database is unusable)
- Tests: `pytest`; lint: `../.init/.linter.sh`
- OpenAPI: `python -m src.api.generate_openapi` writes `interfaces/openapi.json`

## Database wiring

Settings (`app/core/config.py`) resolve `DATABASE_URL` (runtime role `asset_app`, DML only) and
`MIGRATION_DATABASE_URL` (`asset_migrator`, DDL) from the environment, then from the git-ignored
`database_workspace/database/database_urls.env` generated by the database container's `startup.sh`
(override the path with `DATABASE_URLS_FILE`). Start the database first
(`cd ../../database_workspace/database && ./startup.sh`). URLs are never logged.

Migrations (run as the migration role):

```
source venv/bin/activate
alembic upgrade head
```

## Worker role

The worker is a separate process of the same backend artifact, not a separate container. It claims
durable PostgreSQL leases for nightly scoring and staged-photo cleanup, dispatches the transactional
outbox, and logs freshness for the last completed nightly run and oldest pending outbox event.

```
source venv/bin/activate
python -m app.worker.main --check
python -m app.worker.main
```

Use `python -m app.worker.main --once` for one non-looping local cycle. Configure SMTP only through
the documented `SMTP_*` environment variables. Without `SMTP_HOST` and `SMTP_TO`, outbox events
remain retryable rather than being silently dropped.

## Layout

`app/main.py` (factory), `app/api/` (health, `/api/v1`), `app/core/` (settings, logging, errors,
problem+json, request guards), `app/db/` (base, session, unit of work, model registry),
`app/modules/*/models.py` (13 tables), `app/worker/` (durable scheduler and jobs), and
`migrations/` (Alembic).
